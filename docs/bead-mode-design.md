# 拼豆模式（导入图纸）功能设计文档

## 功能概述

拼豆模式允许用户导入已生成的拼豆图纸，进入专门的拼豆辅助界面，通过色块高亮功能帮助用户对照实物进行拼豆。

---

## 核心需求

### 1. 图纸唯一标识
- 在生成图纸时，右下角嵌入魔红色标记（#FF00FF）
- 用于验证图纸是否为本工具生成
- 标记位置：距离右下角 9px，大小 4x4 像素

### 2. 导入图纸功能
- 主页面添加"导入图纸"按钮（与"上传照片"同一级）
- 仅支持 PNG 格式
- 验证魔红色标记，非本工具生成的图纸无法导入
- 导入后进入拼豆模式

### 3. 拼豆模式界面
- **展示范围**：只展示核心像素格区域（不包括坐标轴）
- **拖动功能**：支持鼠标/触摸拖动
- **缩放功能**：支持 0.5x - 5x 缩放
- **色号清单**：底部横向滚动条显示

### 4. 色块高亮功能（核心）
- 选择色号 → 该色号对应的像素格保持原样
- 其他像素格灰暗处理
- 背景色（H2, H9）不参与高亮
- 再次点击或"清除高亮"按钮恢复

## 技术方案讨论

### 色号识别方案

#### 方案 A：OCR 文字识别
- 使用 Tesseract.js 等 OCR 库
- 对每个像素格进行文字识别
- **优点**：准确读取色号编号（如 H7, H16, G18）
- **缺点**：
  - 需要引入 OCR 库，增加包体积
  - 识别速度可能较慢
  - 小字体识别准确率可能不高

#### 方案 B：颜色匹配（当前尝试）
- 对每个像素格中心点采样颜色
- 匹配最近的 MARD 色卡颜色
- **优点**：实现简单，速度快
- **缺点**：
  - 采样点可能采到网格线或色号文字
  - 导致颜色识别错误
  - 高亮逻辑不准确

### 当前问题

1. **色号识别不准确**
   - 使用颜色匹配方案时，采样点可能采到网格线或文字
   - 导致识别出的色号与实际不符
   - 用户反馈：选择 H5 深灰，高亮的却是 H16 和 G166

2. **反向解析参数不确定**
   - 图纸生成时使用多种参数（cellSize 12 或 20）
   - 导入时不知道原图使用的参数
   - 尝试多种参数组合，自动选择色号数量最多的

3. **色号清单不完整**
   - 反向解析时丢失部分色号
   - 用户反馈色号清单只有一种颜色

## 用户建议的方案

### 逐像素格遍历 + 色号编号识别

**核心思路：**
1. 对红框内的核心区域进行逐像素格遍历
2. 每个像素格内已经写有色号编号（如 H7, H16, G18）
3. 识别每个像素格内的色号文字
4. 记录：色号编号 → 像素坐标（行、列）的映射关系
5. 统计色号清单及其对应的像素格数量
6. 高亮时根据映射关系针对性处理

**技术实现：**
- 需要 OCR 或图像识别技术
- 或者优化颜色匹配方案（多点采样，排除网格线/文字）

---

## 改进方向

### 短期方案：优化颜色匹配
1. 对每个像素格进行**多点采样**（如 9 个点：中心 + 8 个方向）
2. 取出现次数最多的颜色（排除白色/灰色网格线）
3. 避开网格线和文字的干扰

### 长期方案：引入 OCR
1. 使用 Tesseract.js 进行文字识别
2. 识别每个像素格内的色号编号
3. 建立准确的色号→坐标映射

## 参考资料

### MARD 色卡
- MARD 291 完整色卡（291 色）
- MARD 221 标准色板
- MARD 24 基础色板

### 图纸生成参数
- `generatePatternImage`: cellSize=12, topPadding=40, leftPadding=40
- `generatePatternImageWithColorList`: cellSize=20, topPadding=60, leftPadding=60

### 魔红色标记
- 颜色：#FF00FF (RGB: 255, 0, 255)
- 位置：距离右下角 9px
- 大小：4x4 像素
